# CoinePro-FX — دو چیز که اپ اندروید لازم دارد

این متن مستقل است. هیچ سند دیگری لازم نیست خوانده شود.

اپ اندروید CoinePro دو بک‌اند جدا دارد: CoinePro-FX برای فارکس (XAUUSD / XAGUSD) و
TradeYar برای کریپتو. این درخواست فقط دربارهٔ CoinePro-FX است.

آدرس پایه‌ای که اپ استفاده می‌کند: `https://coineprofx.com/api/`
مسیرهای زیر نسبت به همین‌اند، یعنی `user/market-intelligence` می‌شود
`https://coineprofx.com/api/user/market-intelligence`.

## ۱. اندپوینت اخبار و تقویم — دادهٔ آن را **همین حالا دارید**

شما پرسیدید «اندپوینت اخبار بازار برای اپ اصلاً نداریم — بسازیم یا از اپ برداشته
شود؟» پاسخ: بسازید — و کارِ کمی است، چون داده‌اش ساخته شده و فارسی هم هست.

`run_news_worker.py` هر بار این دو کلید را در Redis می‌نویسد:

- `bn:news` — اخبار مؤثر بر بازار، عنوان و خلاصه **به فارسی** (توسط Claude داخل
  سرور)، با کلیدهای `src` / `title` / `summary` / `url` / `sc`، انقضای ۷۲۰۰ ثانیه.
- `bn:calendar` — تقویم اقتصادی هفتگی از faireconomy/ForexFactory، فقط رویدادهای
  `high` و `medium`، عنوان‌ها فارسی‌شده، با کلیدهای `title` / `country` / `date` /
  `impact` / `forecast` / `previous`.

و `src/api/routes/bazaarnama.py` همین‌ها را در `GET /academy/bn/news` و
`GET /academy/bn/calendar` به‌صورت `{"items": [...]}` سرو می‌کند.

**پس درخواست فقط این است: یک آداپتور نازک زیر `user/` که همان دو کلید Redis را به
شکل زیر بازنویسی کند.** خط جدیدی از داده لازم نیست.

```
GET user/market-intelligence
Authorization: Bearer <access_token>
```

### نگاشت از چیزی که دارید

| فیلد اپ | از کجا |
| --- | --- |
| `news[].source` | `src` |
| `news[].title` / `summary` / `url` | همان‌ها |
| `news[].id` | هرچه پایدار باشد؛ هش url یا title کافی است |
| `news[].published_at` | worker الان تاریخ نگه نمی‌دارد — از `e.published` در feedparser بردارید |
| `news[].impact` | از همان `sc` که دارید: `sc>=3` → `high`، بقیه `medium` |
| `news[].sentiment` | اگر ندارید `null` بفرستید؛ اپ آن را «نامشخص» می‌گیرد و رنگی نمی‌دهد |
| `calendar[].scheduled_at` | `date` |
| `calendar[].title` / `country` / `impact` / `forecast` / `previous` | همان‌ها |

### چند نکته که اپ روی آن‌ها حساب کرده

- **`published_at` و `scheduled_at` اجباری‌اند.** ردیفی که تاریخ نداشته باشد کلاً
  انداخته می‌شود — الان `bn:news` تاریخ ندارد و این تنها چیزی است که واقعاً باید
  اضافه شود.
- **قالب تاریخ:** اپ هر سه شکل `2026-08-25T18:00:00Z` و
  `2026-08-25T18:00:00+00:00` (همان چیزی که `datetime.isoformat()` می‌دهد) و
  `2026-08-25T18:00:00` (بدون منطقه، UTC خوانده می‌شود) را می‌خواند. عدد epoch را
  نه. تقویم شما `date` را رشتهٔ ISO می‌دهد که خوب است.
- **`impact`**: `low` / `medium` / `high`. تقویم فقط وقتی به کاربر هشدار می‌دهد که
  `high` باشد.
- **`sentiment`**: `bullish` / `bearish` / `neutral` (اپ `positive` و `negative` را
  هم می‌پذیرد). هر چیز دیگر و `null` → نامشخص.
- **`relevance`**: آرایه‌ای از `gold` (یا `xau` / `xauusd`) و `silver` (یا `xag` /
  `xagusd`). اپ از این برای هشدار «تا شش ساعت دیگر رویداد پرتأثیری روی طلا هست»
  استفاده می‌کند؛ خالی گذاشتنش یعنی آن هشدار هرگز ظاهر نمی‌شود. برای تقویم
  می‌توانید از `country`/`currency` استنتاج کنید: `USD` → `["gold","silver"]`.
- **`stale` را صریح بفرستید.** نبودنش «کهنه» فرض می‌شود، چون خبر بی‌تاریخ‌ِ اعتبار
  از خبر زنده قابل تشخیص نیست و اشتباه در جهت امن بهتر است. `bn:news` انقضای ۷۲۰۰
  ثانیه دارد؛ همان معیار خوبی است.
- **`url` باید `https` باشد**، وگرنه دور ریخته می‌شود.
- `id`، `title`، `source` اجباری‌اند.
- اگر خبری نیست: `"news": []` — نه ۴۰۴ و نه ۲۰۴.

## ۲. فیلدهای اشتراک در `user/me`

اپ حالا یک کارت اشتراک روی صفحهٔ اصلی دارد که **فقط** برای کسی که اشتراک دارد
نمایش داده می‌شود. برای بقیه هیچ چیز — نه حالت خالی، نه پیشنهاد خرید — و هیچ
امکانی هم بسته نمی‌شود. سیگنال‌ها، اجرای معامله و بقیه برای هر حساب واردشده باز
است. تنها چیزی که یک امکان را می‌بندد، ردِ صریح خود سرور به یک درخواست است.

`_profile_dict` در `user_panel.py` هر چهار فیلد لازم را **همین حالا دارد** و اپ
همان‌ها را می‌خواند: `is_paid`، `is_vip`، `plan`، `plan_expires_at`. فقط دو نکته:

1. **`plan` را فارسی بدهید.** الان از جدول `subscriptions` می‌آید و ممکن است
   `monthly` باشد. اپ نام طرح را **عیناً** می‌نویسد و هرگز ترجمه نمی‌کند — چون حق
   ندارد اسمی را که خودش نگذاشته ترجمه کند. پس اگر انگلیسی بفرستید، کاربر
   فارسی‌زبان `monthly` می‌بیند.
2. **`plan_expires_at`** الان `.isoformat()` است، یعنی `+00:00` می‌دهد نه `Z`.
   این از سمت اپ درست شد و هر دو شکل خوانده می‌شود — کاری لازم نیست، فقط برای
   اطلاع.

**مهم:** اپ هرگز خودش تصمیم نمی‌گیرد اشتراکی تمام شده. اگر `plan_expires_at` گذشته
باشد ولی `is_paid` هنوز `true` باشد، اپ اشتراک را زنده می‌داند. تصمیم با سرور است
— ساعتِ یک روز جلوترِ گوشی نباید چیزی را که کاربر بابتش پول داده از او بگیرد.

## ۳. یک چیز کوچک در `user/auth/methods`

خروجی این اندپوینت `ai_signals` و `assistant` ندارد، در حالی که این سرور هر دو
محصول را دارد. TradeYar هر دو را گزارش می‌کند.

اپ فعلاً نبودِ این دو را «نامشخص» می‌گیرد نه «خاموش»، پس چیزی خراب نیست. ولی اگر
اضافه‌شان کنید اپ می‌تواند وقتی پلِ مدل خواب است صفحه را خاموش کند به‌جای اینکه
پر از کارِ شکست‌خورده شود:

```json
"ai_signals": true,
"assistant": true
```

`ai_signals` بهتر است دسترسیِ واقعیِ مدل را نشان دهد، نه یک فلگ ثابت.

---

## چیزی که لازم **نیست**

- صفحهٔ خرید اشتراک داخل اپ نمی‌خواهیم.
- اندپوینت جدا برای «آیا اشتراک دارم» نمی‌خواهیم؛ همان `user/me` کافی است.
- خطِ خبریِ تازه نمی‌خواهیم؛ همان `bn:news` و `bn:calendar` کافی است.
