# CoinePro-FX — چهار چیز، بعد از خواندن سورس

ریپو را باز کردید و کدِ سرور را خط‌به‌خط با آنچه اپ صدا می‌زند مقایسه کردم. این
متن مستقل است.

آدرس پایه‌ای که اپ استفاده می‌کند: `https://coineprofx.com/api/`

سه چیزی که خودتان قبلاً گفته بودید در اپ درست شد و دیگر لازم نیست کاری بکنید:
`user/ai-vision/jobs` (اپ `user/ai/vision/jobs` می‌زد)، `user/ai/chat` (اپ
`user/ai/assistant/messages` می‌زد)، و `plan_expires_at` که `.isoformat()` است و
`+00:00` می‌دهد نه `Z` — اپ حالا هر دو را می‌خواند.

---

## ۱. سیگنال‌ها پشت VIP بمانند — فقط یک چیز کم دارد

تصمیم محصول این است: **سیگنال و کپی‌ترید فقط برای مشترکین**، بقیهٔ امکانات برای
هر کاربر واردشده باز. یعنی `require_vip` روی `/public/signals/active` و
`/public/signals/recent` درست است. دست نزنید.

مشکل چیز دیگری است: وقتی کاربرِ بدون اشتراک این را صدا می‌زند، پاسخ ۴۰۳ است و اپ
راهی ندارد بفهمد این «اشتراک لازم است» بوده یا «توکنت باطل شده» — هر دو ۴۰۳
هستند. نتیجه‌اش این می‌شود که کاربر بدون اشتراک یا فهرست خالی می‌بیند یا بدتر،
از حساب بیرون انداخته می‌شود.

**درخواست: در بدنهٔ آن ۴۰۳ یک کد ماشین‌خوان بگذارید.** مثلاً:

```json
{"detail": {"code": "membership_required",
            "message": "دیدنِ سیگنال‌ها نیازمند اشتراک فعال است."}}
```

اپ آن `code` را می‌خواند و متن اشتراک را نشان می‌دهد به‌جای اینکه نشست را باطل
کند. `message` هم عیناً نمایش داده می‌شود — اپ متن سرور را ترجمه یا بازنویسی
نمی‌کند، پس هرچه بنویسید همان چیزی است که کاربر می‌خواند.

(TradeYar این را با یک فیلد `membership_required: true` در پاسخ ۲۰۰ حل کرده. هر
کدام از دو روش برای اپ کار می‌کند؛ فقط باید قابلِ تشخیص از ۴۰۳ِ احراز هویت باشد.)

## ۲. اندپوینت جزئیات یک سیگنال برای اپ وجود ندارد

اپ صفحهٔ جزئیات سیگنال دارد. `/signals/{signal_id}` هست ولی
`Depends(get_current_admin)` دارد، و زیر `public` فقط فهرست است.

**سؤال:** `GET /public/signals/{id}` اضافه می‌کنید (همان `_pub_signal` برای یک
ردیف)، یا صفحهٔ جزئیات را از همان فهرستی که قبلاً گرفته شده پر کنیم؟

گزینهٔ دوم کار می‌کند ولی یک عیب دارد: اگر کاربر از روی نوتیفیکیشن مستقیم وارد
جزئیات یک سیگنال شود، اپ آن سیگنال را در حافظه ندارد و باید کل فهرست را بگیرد و
در آن بگردد. برای یک صفحه که با یک شناسه باز می‌شود، این گران و شکننده است.

## ۳. شکل شیء سیگنال با چیزی که اپ می‌خواند فرق دارد

`_pub_signal` این را می‌دهد:

```
id, symbol, direction, signal_type, entry_price, sl, tp1, tp2, tp3,
signal_score, timeframe, status, close_reason, pnl_pips, hit_target,
created_at, closed_at
```

اپ این را می‌خواند:

```
id, market, symbol, direction, status, timeframe, strategy, confidence,
entry, entry_zone, stop_loss, targets[{level, price, hit}], risk_reward_tp1,
current_quote{price, ts, is_stale}, rationale, score_breakdown, result, …
```

**نکته‌ای که ارزش گفتن دارد:** TradeYar دقیقاً همین شکل دوم را می‌دهد. یعنی اگر
شما هم همان را بدهید، اپ یک پارسر برای هر دو پلتفرم دارد به‌جای دو تا — و هر
تفاوتی که بماند، جایی است که بعداً یکی از دو پلتفرم بی‌صدا خراب می‌شود.

**سؤال:** ترجیح می‌دهید شما نگاشت را سمت سرور بدهید (یک تابع کوچک روی
`_pub_signal`)، یا اپ نگاشت را سمت خودش انجام دهد؟

اگر سمت خودتان می‌دهید، این‌ها را لازم داریم و الان ندارید:
- `market` — ثابت `"forex"`
- `targets` — از `tp1/tp2/tp3` با `level` و `price`
- `risk_reward_tp1` — از `entry_price`، `sl` و `tp1`
- `current_quote` — روی `active` قیمت زنده را دارید (`current_price`)؛ فقط
  `ts` و `is_stale` کم است
- `entry_zone`، `rationale`، `score_breakdown` — اگر ندارید `null` بفرستید،
  اپ هر سه را اختیاری می‌خواند

## ۴. لایهٔ اجرای معامله — اپ روی مدلی نوشته شده که شما ندارید

اپ هشت مسیر `user/signals/execution/*` صدا می‌زند و همه ۴۰۴ می‌دهند. شما قبلاً
جایگزین‌ها را گفتید و درست بودند:

| اپ می‌خواهد | شما دارید |
| --- | --- |
| پوزیشن‌های باز | `user/mobile/portfolio` |
| تاریخچه | `user/trade-history`, `.../stats`, `.../report`, `.../daily` |
| بستن یک پوزیشن | `user/copy/close-position` |
| بستن همه | `user/copy/close-all` |
| اتصال بروکر | `user/broker-servers`, `user/account/link`, `user/copy-config`, `user/copy-status` |

تفاوت واقعی این است که اپ روی مدلِ «یک سفارش تکی برای یک سیگنال» نوشته شده و
شما مدلِ «کپی‌تریدینگ» دارید — کاربر یک حساب متصل می‌کند و سرویس خودش معامله
می‌کند. این دو یکی نیستند و با تغییر مسیر حل نمی‌شوند.

**سؤال:** درست است که اپ صفحهٔ «اجرا» را بردارد و به‌جایش «اتصال حساب + وضعیت
کپی + تاریخچه» بگذارد؟ یعنی کاربر در اپ سفارش نمی‌فرستد، بلکه حسابش را وصل
می‌کند و نتیجه را می‌بیند.

اگر بله، دو چیز لازم داریم که مطمئن نیستم هست:
1. آیا `user/copy-config` می‌تواند از داخل اپ **نوشته** شود (اندازهٔ پوزیشن،
   نمادها، ریسک)، یا فقط خواندنی است؟
2. `user/copy-status` چه چیزی برمی‌گرداند؟ اپ لازم دارد بداند «وصل است / در حال
   کار است / متوقف شده / خطا دارد» را از کجا بخواند.

## ۵. دو چیز کوچک

**`user/auth/methods` دو فیلد کم دارد.** `ai_signals` و `assistant` را نمی‌فرستد،
با اینکه این سرور هر دو محصول را دارد. TradeYar هر دو را می‌فرستد. اپ فعلاً
نبودشان را «نامشخص» می‌گیرد نه «خاموش»، پس چیزی خراب نیست — ولی اگر اضافه‌شان
کنید اپ می‌تواند وقتی پلِ مدل خواب است صفحه را خاموش کند به‌جای پر کردنش از کارِ
شکست‌خورده. `ai_signals` بهتر است دسترسیِ واقعیِ مدل را نشان دهد نه یک فلگ ثابت.

**`plan` را فارسی بدهید.** اپ نام طرح را عیناً می‌نویسد و هرگز ترجمه نمی‌کند، چون
حق ندارد اسمی را که خودش نگذاشته ترجمه کند. الان از جدول `subscriptions` می‌آید و
ممکن است `monthly` باشد؛ کاربر فارسی‌زبان همان را می‌بیند.

## ۶. اخبار بازار — درخواستِ قبلی، حالا خیلی کوچک‌تر

قبلاً نوشتم «بسازید». حالا که سورس را دیده‌ام: **دادهٔ آن را دارید.**

`run_news_worker.py` این دو کلید Redis را می‌نویسد:
- `bn:news` — عنوان و خلاصه **به فارسی**، کلیدهای `src`/`title`/`summary`/`url`/`sc`
- `bn:calendar` — تقویم ForexFactory، فقط `high` و `medium`، عنوان‌ها فارسی

و `academy/bn/news` و `academy/bn/calendar` همین‌ها را سرو می‌کنند.

پس فقط یک آداپتور نازک زیر `user/` لازم است:

```
GET user/market-intelligence
```

```json
{
  "server_time": "2026-08-25T09:14:00Z",
  "news": [{
    "id": "…", "title": "…", "summary": "…", "source": "ForexLive",
    "url": "https://…", "published_at": "2026-08-25T18:00:00Z",
    "sentiment": "bearish", "impact": "high",
    "relevance": ["gold"], "stale": false
  }],
  "calendar": [{
    "id": "…", "title": "…", "country": "US", "currency": "USD",
    "scheduled_at": "2026-08-26T12:30:00Z", "impact": "high",
    "actual": null, "forecast": "0.3%", "previous": "0.2%",
    "relevance": ["gold", "silver"], "stale": false
  }]
}
```

نگاشت: `src→source`، `sc>=3→impact:"high"`، بقیه `medium`. تقویم را از
`bn:calendar` مستقیم بردارید (`date→scheduled_at`).

**تنها چیزی که واقعاً کم است:** `bn:news` تاریخ انتشار نگه نمی‌دارد. اپ ردیفِ
بی‌تاریخ را می‌اندازد. `e.published` در feedparser هست — فقط ذخیره‌اش کنید.

قالب تاریخ: اپ `Z` و `+00:00` و بدونِ منطقه (UTC خوانده می‌شود) هر سه را می‌خواند.
عدد epoch را نه. `sentiment` اگر ندارید `null` بفرستید. `stale` را صریح بفرستید —
نبودنش «کهنه» فرض می‌شود.
