Generated by `scripts/quality/gen_parity_matrix.py` from the render tests' `@Config(qualifiers = …)`; do not edit by hand. A cell is the count of renders that exist for that screen at that window, with the tests named beneath the table. `—` is a window with no render, and is meant to be read as such.

## The fold, on the JVM

A hinge cannot be rendered off-device — `androidx.window` needs an activity and Robolectric reports no folding features — so the fold columns are the window-class columns plus these pure assertions on the posture mapping and the decisions taken from it:

- `CoineProFoldTest` — `core/designsystem/src/test/kotlin/com/coinepro/core/designsystem/CoineProFoldTest.kt`
- `ChartFoldTest` — `feature/chart/src/test/kotlin/com/coinepro/feature/chart/ChartFoldTest.kt`
- `WindowClassTest` — `core/designsystem/src/test/kotlin/com/coinepro/core/designsystem/WindowClassTest.kt`
- `ChartPaneCapTest` — `feature/chart/src/test/kotlin/com/coinepro/feature/chart/ChartPaneCapTest.kt`

What a device would add, and this matrix does not claim: the hinge's actual dp on a Galaxy Z Fold / Pixel Fold, the table-top chart on glass, and the transition when a fold happens mid-gesture. See `docs/engineering/REPORT.md` §4.
