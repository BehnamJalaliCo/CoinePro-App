# درخواست ۵ — تریدیار

**به:** تیم TradeYar
**از:** اپ اندروید کوین‌پرو
**تاریخ:** ۱۴۰۵/۰۶/۰۵
**وضعیت اپ:** نسخهٔ ۱٫۲۰٫۱ ساخته و امضا شده. همهٔ موارد زیر تنها چیزهایی هستند که مانده و سمت شماست.

---

## ۰) اطلاع‌رسانی امنیتی — مخزن اپ اندروید عمومی شد

مخزن `BehnamJalaliCo/CoinePro-App` از خصوصی به عمومی تغییر کرد (برای انتشار صفحات حقوقی در
GitHub Pages که Google Play الزام می‌کند).

**چه چیزی از شما در آن هست:** نام دامنه‌های `tradeyar.trade-future.ir` و
`user.tradeyar.trade-future.ir`، و فهرست مسیرهای HTTP که اپ صدا می‌زند — شامل `api/mobile/v1/*` و
روت‌های عمومی. این‌ها از خودِ فایل APK هم با ده دقیقه کار قابل استخراج بودند، پس چیز تازه‌ای به یک
مهاجم جدی نمی‌دهد.

**چه چیزی نیست:** هیچ توکن، هیچ کلید، هیچ رمز. کل تاریخچهٔ گیت — ۱۳٬۲۹۱ آبجکت، نه فقط درخت فعلی —
اسکن شد و هیچ اعتباری در هیچ کامیتی نبود.

**آنچه از شما می‌خواهیم:** اگر هر روتی امنیتش به ناشناخته‌بودنِ آدرسش تکیه دارد، این را اعلان
رسمی بدانید. مشخصاً روت‌های عمومی (`/api/v1/public/*`، `/api/demo/signals`) اگر محدودکنندهٔ نرخ
ندارند، الان وقتش است.

اسناد قدیمی‌تر در `docs/` نام فایل‌های داخلی سرور و کلیدهای Redis شما را هم نوشته‌اند. اگر بخواهید
پاکشان می‌کنیم — بگویید. از این به بعد اسناد فقط مرزِ HTTP را می‌نویسند.

## ۱) حذف حساب — بلوکرِ انتشار در Google Play

بدون این، اپ منتشر نمی‌شود. صفحهٔ بیرونی‌اش منتشر شده و آن نیمهٔ الزام را پوشش می‌دهد؛ نیمهٔ داخل
اپ روت شما را می‌خواهد.

```
DELETE api/mobile/v1/account
```

* احراز: همان Bearer موبایل. حساب همان است که توکن به آن اشاره می‌کند — هیچ شناسه‌ای در بدنه.
* موفق: `204` بدون بدنه. اپ بلافاصله خارج می‌شود.
* رد: `409` با **پیام فارسی قابل نمایش** — مثلاً موجودی تسویه‌نشده. اپ همان جمله را عیناً نشان
  می‌دهد.
* و در `auth/methods` این فیلد:

```json
{ "accountDeletion": true }
```

نبودنش `false` خوانده می‌شود و اپ دکمه را نشان نمی‌دهد. **تا وقتی نساخته‌اید چیزی خراب نیست** —
`404` را «ارائه نمی‌شود» می‌خواند و کاربر را به صفحهٔ بیرونی می‌فرستد.

## ۲) ورود با گوگل — یک سؤال، شاید کار شما صفر باشد

اپ `googleClientId` را از `user/auth/config` می‌گیرد، نه از فایل Firebase خودش. برای اینکه ورود با
گوگل روی گوشی کار کند، اثر انگشت امضای اپ باید در **همان پروژهٔ گوگل‌کلادی ثبت باشد که آن
`client_id` را صادر کرده**.

**سؤال: آن `client_id` مال کدام پروژه است؟**

* اگر مال پروژهٔ `coinepro-app` (شمارهٔ `1033486124390`) است، کاری لازم نیست؛ مالک ثبتش کرده.
* اگر مال پروژهٔ خودتان است، این SHA-1 را در آن پروژه ثبت کنید، برای پکیج `com.coinepro.app`:

```
5D:E8:7F:4B:B3:E8:35:6B:4E:98:1E:D4:DA:63:0B:A7:77:5F:9A:A8
```

بدون این، ورود با گوگل روی نسخهٔ ریلیز با `DEVELOPER_ERROR` رد می‌شود و پیام خطایش هم چیزی به
کاربر نمی‌گوید.

---

## ۳) بازیابی رمز — یک فایل استاتیک

اپ لینک `https://user.tradeyar.trade-future.ir/reset` را به‌عنوان App Link تأییدشده claim می‌کند،
چون توکن بازنشانی یک اعتبارنامه است و اسکیم اختصاصی را هر اپی می‌تواند بدزدد. اندروید این را فقط
وقتی تأیید می‌کند که این فایل روی همان دامنه سرو شود:

```
https://user.tradeyar.trade-future.ir/.well-known/assetlinks.json
```

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "com.coinepro.app",
    "sha256_cert_fingerprints": [
      "96:12:AB:6C:BF:BB:4F:4F:FB:F1:51:D8:60:2C:12:9D:CC:E8:A9:77:1E:85:46:69:E6:63:87:0F:04:04:FB:D0"
    ]
  }
}]
```

`Content-Type: application/json`، بدون ریدایرکت، بدون احراز.

بدون آن هیچ چیز خراب نمی‌شود — لینک در مرورگر باز می‌شود، که برای کسی که ایمیل را روی دسکتاپ باز
می‌کند به‌هرحال باید کار کند. با آن، در اپ باز می‌شود.

> اگر بعداً از Play App Signing استفاده کنید، گوگل با کلید خودش دوباره امضا می‌کند و اثر انگشت
> عوض می‌شود. آن موقع اثر انگشتِ Play Console را هم به همین آرایه اضافه کنید — هر دو با هم.

## ۴) کندل عمومی — مهمان نمودار ندارد

اپ حالا بدون ثبت‌نام باز می‌شود. مهمان فهرست بازار و اخبار را می‌بیند، ولی روی هیچ نمادی نمی‌تواند
نمودار باز کند — که دقیقاً اولین کاری است که کاربر تازه می‌کند.

```
GET /api/v1/public/candles/{symbol}?tf=1h&limit=300
```

همان شکلِ `{t,o,h,l,c,v}` که سطح احرازشده می‌دهد، `t` بر حسب ثانیه. نرخ محدود هرچقدر لازم است.

---

## ۵) مسیر عضویت — سه روت

اپ شرایط عضویت را نشان می‌دهد ولی **لینک ثبت‌نام را عمداً ندارد**، چون لینکی که در اپ کامپایل شود
روزی که عوض شود غلط می‌شود، و لینک غلط یعنی حسابی که در سامانهٔ صرافی به کوین‌پرو وصل نمی‌شود و
بعداً قابل احراز نیست. آن را از سرور می‌خواهیم:

```
GET /api/v1/public/membership
→ { "lbankReferralUrl": "...", "ourbitReferralUrl": "...",
    "minDepositUsdt": 50, "copyTradeExchanges": ["lbank"] }
```

و دو تای دیگر، هر دو با Bearer موبایل:

```
POST api/mobile/v1/membership/uid     { "exchange": "lbank", "uid": "..." }
GET  api/mobile/v1/membership/status  → کدام گام مانده
```

امروز ثبت UID با `regToken` کار می‌کند که موبایل ندارد.

## ۶) تأیید ساده

روت‌های عمومی — `/api/v1/public/prices`، `/prices/universe`، `/tickers`، `/api/v1/news/list`،
`/api/demo/signals`، `/api/v1/public/community` — روی همان دامنه‌ای می‌مانند که اپ الان به آن وصل
است؟ اگر قرار است جابه‌جا شوند، **حالا** بگویید، نه بعد از انتشار.
