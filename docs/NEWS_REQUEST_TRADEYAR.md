# TradeYar — سه چیز که اپ اندروید لازم دارد

این متن مستقل است. هیچ سند دیگری لازم نیست خوانده شود.

آدرس پایه‌ای که اپ استفاده می‌کند: `https://tradeyar.trade-future.ir/`

---

## ۱. اندپوینت اخبار کریپتو — دادهٔ آن را **همین حالا دارید**

اپ یک صفحهٔ اخبار بازار دارد که تا الان فقط از بک‌اند فارکس تغذیه می‌شد. یعنی
کاربری که روی TradeYar بود، خبرِ طلا و تصمیم نرخ بهره را زیر عنوان «کریپتو»
می‌دید. این جواب بد نیست، **غلط** است: تصمیم نرخ بهره ربطی به لیست شدن یک توکن
ندارد و آنلاک یک توکن ربطی به طلا. حالا اپ برای هر پلتفرم جدا می‌خواند.

خبر فارسی را دارید: جدول `news_posts` با `title_fa`، `summary_fa`، `source`،
`source_url`، `importance`، `tags`، `published_at`، `content_type`، `status`
— و `app/api/routers/public/news.py` همین حالا در `GET /list` سرو می‌کندش.

**پس درخواست فقط یک آداپتور نازک است روی همان جدول:**

```
GET api/mobile/v1/market-intelligence
Authorization: Bearer <access_token>
```

```json
{
  "server_time": "2026-08-25T09:14:00Z",
  "news": [
    {
      "id": "ty-2026-08-25-001",
      "title": "بایننس لیست شدن توکن X را اعلام کرد",
      "summary": "معاملات از ساعت ۱۲ به وقت گرینویچ آغاز می‌شود.",
      "source": "CoinDesk",
      "url": "https://www.coindesk.com/…",
      "published_at": "2026-08-25T08:30:00Z",
      "sentiment": "bullish",
      "impact": "medium",
      "relevance": ["crypto"],
      "stale": false
    }
  ],
  "calendar": []
}
```

### نگاشت از چیزی که دارید

| فیلد اپ | از کجا |
| --- | --- |
| `news[].id` | `id` یا `slug` |
| `news[].title` | `title_fa` |
| `news[].summary` | `summary_fa` |
| `news[].source` | `source` |
| `news[].url` | `source_url` |
| `news[].published_at` | `published_at` |
| `news[].impact` | از `importance` |
| `news[].sentiment` | اگر ندارید `null` بفرستید |
| `news[].relevance` | `["crypto"]` برای همه کافی است |

فیلتر: `status = 'published'` و `content_type = 'news'`، مرتب بر اساس
`published_at` نزولی، ۲۰ تا ۵۰ ردیف. اپ صفحه‌بندی نمی‌کند.

### نکاتی که اپ روی آن‌ها حساب کرده

- **`calendar` را خالی بفرستید** (`[]`). تقویم اقتصادی کلان کارِ سمت فارکس است و
  در صفحهٔ کریپتو جایی ندارد. کلید باید باشد، محتوایش نه.
- **قالب تاریخ:** اپ هر سه شکل `2026-08-25T08:30:00Z` و
  `2026-08-25T08:30:00+00:00` (همان چیزی که `.isoformat()` شما می‌دهد) و
  `2026-08-25T08:30:00` را می‌خواند. **عدد میلی‌ثانیه را نه.** می‌دانم در `alerts`
  و `notifications` از `_ms` استفاده می‌کنید و آنجا درست است؛ اینجا رشتهٔ ISO باشد،
  چون این اندپوینت همان پارسری را دارد که سمت فارکس دارد و یک صفحه نمی‌تواند دو
  زبان زمانی داشته باشد.
- **`impact`**: `low` / `medium` / `high`. اگر `importance` عدد است، نگاشت کنید.
- **`sentiment`**: `bullish` / `bearish` / `neutral` (اپ `positive` و `negative` را
  هم می‌پذیرد). `null` → نامشخص و بی‌رنگ.
- **`relevance`**: آرایه. الان اپ `crypto` و `digital_assets` را می‌شناسد. اگر
  بعداً خواستید خبر را به یک جفت‌ارز خاص ببندید بگویید تا اپ آن را هم بشناسد —
  فعلاً `["BTCUSDT"]` نادیده گرفته می‌شود.
- **`stale` را صریح بفرستید.** نبودنش «کهنه» فرض می‌شود.
- **`url` باید `https` باشد**، وگرنه دور ریخته می‌شود.
- `id`، `title`، `source`، `published_at` اجباری‌اند؛ ردیفی که یکی را نداشته باشد
  نمایش داده نمی‌شود.
- اگر خبری نیست: `"news": []` — نه ۴۰۴، نه ۲۰۴.

## ۲. اشتراک — و آن مشکلی که خودتان پیدا کردید

شما نوشتید: «`vip_members.user_id` کلید خارجی به `users(user_id)` دارد — یک حساب
ایمیل‌محور ساختاراً نمی‌تواند اشتراک داشته باشد.»

**تصمیم گرفته شد و این است:**

> کسی که با ایمیل ثبت‌نام می‌کند صرفاً نمی‌تواند اشتراک داشته باشد — و اشکالی
> ندارد. ولی هیچ امکانی هم نباید از او گرفته شود. سیگنال‌ها، کپی‌ترید و بقیهٔ
> امکانات باید برای کاربر عادی کاملاً باز باشد. اشتراک فقط برای کسانی که دارند،
> مراحل و اطلاعاتش باز می‌شود.

یعنی:

1. **`vip_members` را دست نزنید و کلید خارجی را نشکنید.**
2. **هیچ اندپوینتی نباید به‌خاطر نداشتن اشتراک ۴۰۳ بدهد**، مگر همان‌هایی که واقعاً
   محصول پولی‌اند و خودتان تصمیم گرفته‌اید. سیگنال‌ها و اجرای معامله باید برای هر
   حساب واردشده کار کنند.
3. **`identity.build_user_payload` این چهار فیلد را اضافه کند.** الان خروجی‌اش
   `userId` / `username` / `fullName` / `verificationStatus` / `lbankUid` / `email`
   / `phone` / `source` / `createdAt` است و هیچ فیلد اشتراکی ندارد — پس اپ برای هر
   کاربر TradeYar کارت اشتراک را پنهان می‌کند، حتی برای عضوی که در `vip_members` هست.

```json
"isPaid": false,
"isVip": false,
"plan": null,
"planExpiresAt": null
```

- حساب ایمیل‌محورِ بدون اشتراک: هر دو `false`. اپ **هیچ چیز** نشان نمی‌دهد.
- حسابی که در `vip_members` هست: `isVip: true`، `plan` نام طرح **به فارسی** — اپ
  آن را عیناً می‌نویسد و ترجمه نمی‌کند — و `planExpiresAt` رشتهٔ ISO.

camelCase بنویسیدشان، مثل بقیهٔ همان payload. اپ هر دو املا را می‌خواند.

**مهم:** اپ هرگز خودش تصمیم نمی‌گیرد اشتراکی تمام شده. اگر `planExpiresAt` گذشته
باشد ولی `isVip` هنوز `true` باشد، اپ اشتراک را زنده می‌داند. تصمیم با سرور است.

## ۳. یک هشدار که قبلاً دادید و هنوز باز است

شما نوشتید: «اگر `POST /venues/lbank` با کلید واقعی بزند، `/executions` سفارش واقعی
می‌فرستد.»

این همچنان درست است و اپ راهی ندارد از بیرون بفهمد کلید ذخیره‌شده واقعی است یا
آزمایشی. اگر LBank حالت testnet یا پرچم `sandbox` دارد، بگویید تا اپ کنار فرم کلید
بنویسد کدام حالت فعال است. اگر ندارد هم بگویید — آن‌وقت اپ متن هشدار را صریح‌تر
می‌کند.

---

## چیزی که لازم **نیست**

- صفحهٔ خرید اشتراک داخل اپ نمی‌خواهیم.
- اندپوینت جدا برای «آیا اشتراک دارم» نمی‌خواهیم؛ همان `me` کافی است.
- خطِ خبریِ تازه نمی‌خواهیم؛ همان `news_posts` کافی است.
