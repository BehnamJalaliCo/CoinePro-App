# پرامپت برای Claude Code روی سرور CoinePro-FX

> این متن را همان‌طور که هست به Claude Code روی سرور فارکس بدهید. هر بخش یک کار مستقل است با
> شرط پذیرش و دستور تأیید. اپ اندروید (Pro Chart) نسخه‌ی **4.42.0** روی این قرارداد بسته شده و
> تا این‌ها انجام نشود، چند بخش از اپ خالی می‌ماند.

---

## زمینه

اپ اندروید `Pro Chart` (مخزن `BehnamJalaliCo/CoinePro-App`) در نسخه‌ی 4.42.0 سه چیز را از روی
گوشی برداشت و به سرور سپرد:

1. **۲۱۵ عکس راهنما** از داخل APK بیرون رفت (۸.۴ مگابایت) — حجم دانلود اپ از ۱۷.۰ به ۹.۲ مگابایت
   رسید. اپ حالا این عکس‌ها را از همین سرور می‌گیرد.
2. **خبر و تقویم اقتصادی** دیگر در نسخه‌ی release مستقیم از Investing.com و ForexFactory خوانده
   نمی‌شود (`DIRECT_THIRD_PARTY_FEEDS=false`). فقط روت‌های خودمان می‌مانند.
3. **Play Integrity** روی سه درخواست حساس فعال شد و سرور باید توکنش را تأیید کند.

`{BASE}` در این سند یعنی همان چیزی که اپ در `BuildConfig.API_BASE_URL` دارد — روی release
`https://coineprofx.com/`.

## کار ۱ — سرو کردن عکس‌های راهنما (اولویت: بالا)

بدون این، «مرکز راهنما» در اپ فقط متن نشان می‌دهد و هیچ عکسی ندارد.

**مسیر:** `GET {BASE}/assets/help/images/<file>.webp`

**منبع فایل‌ها:** در مخزن اپ، پوشه‌ی `assets-cdn/help/images/` — ۲۱۵ فایل WebP، ۸.۴ مگابایت.
اسم فایل‌ها را عوض نکنید؛ `core/help/src/main/assets/help/content.json` دقیقاً به همین نام‌ها
ارجاع می‌دهد و یک تست (`HelpCatalogTest`) این تطابق را نگه می‌دارد.

```bash
# روی سروری که مخزن اپ را دارد یا از آنجا کپی می‌کنید
rsync -a assets-cdn/help/ <static-root>/assets/help/
```

**شرط پذیرش**

- بدون توکن و بدون session پاسخ بدهد (عمومی است).
- `Content-Type: image/webp`.
- کش طولانی: `Cache-Control: public, max-age=2592000, immutable` و `ETag`. فایل‌ها تغییرناپذیرند.
- CORS لازم نیست (اپ اندروید است، مرورگر نیست).
- یک فایل ناموجود باید ۴۰۴ بدهد، نه HTML صفحه‌ی خطا. اپ ۴۰۴ را «عکس ندارد» می‌فهمد و فقط
  زیرنویس را نشان می‌دهد؛ ولی اگر HTML برگردد، لودر عکس تلاش می‌کند آن را decode کند.

**تأیید**

```bash
curl -sI https://coineprofx.com/assets/help/images/chart-toolbar.webp | head -3
# انتظار: HTTP/2 200 و content-type: image/webp
```

## کار ۲ — لوگوی نمادهایی که اپ خودش نکشیده (اولویت: متوسط)

اپ برای هر نمادی که آرت‌ورک برداری دارد، خودش می‌کشد و **هیچ درخواستی نمی‌فرستد**. فقط برای
نمادهای بیرون از آن مجموعه (`SymbolArtwork.covers` = false) این آدرس را صدا می‌زند.

**مسیر:** `GET {BASE}/assets/logo/<SYMBOL>.webp` — `<SYMBOL>` با حروف بزرگ، مثل `EURJPY.webp`.

**شرط پذیرش**

- ۱۲۸×۱۲۸، پس‌زمینه شفاف، WebP.
- عمومی، همان هدرهای کش کار ۱.
- **۴۰۴ کاملاً قابل قبول است** — اپ در آن حالت مونوگرام حرف اول را می‌کشد و چیزی خراب نمی‌شود.
  پس این کار را می‌شود تدریجی و فقط برای نمادهای پرتقاضا انجام داد.

## کار ۳ — صفحات حقوقی روی دامنه‌ی خودمان (اولویت: بالا)

اپ در 4.42.0 آدرس حقوقی را از GitHub Pages به دامنه‌ی برند منتقل کرد:

```
BrandConfig.LEGAL_BASE_URL = https://coineprofx.com/legal
```

سه صفحه باید سرو شود:

| آدرس | محتوا |
|---|---|
| `https://coineprofx.com/legal/terms/` | `docs/legal/TERMS.md` (فارسی) + `TERMS_EN.md` |
| `https://coineprofx.com/legal/privacy/` | `docs/legal/PRIVACY_POLICY.md` (هر دو زبان در یک فایل) |
| `https://coineprofx.com/legal/delete-account/` | صفحه‌ی حذف حساب — Google Play این را جداگانه می‌خواهد |

**شرط پذیرش**

- HTML ساده، بدون نیاز به ورود.
- آدرس‌های قدیمی `behnamjalalico.github.io/CoinePro-App/{terms,privacy,delete-account}/` را با
  301 به این‌ها redirect کنید؛ ایمیل‌ها و لیستینگ قدیمی هنوز آن‌ها را دارند.
- متن نسخه‌ی داخل اپ و نسخه‌ی وب باید یکی باشد. منبع واحد `docs/legal/` در مخزن اپ است و
  `scripts/release/sync-legal-documents.py` آن را داخل اپ کپی می‌کند؛ وب هم باید از همان‌جا بیاید.

## کار ۴ — روت خبر: `academy/bn/news` (اولویت: بالا)

اپ در نسخه‌ی release دیگر Investing.com را از روی گوشی نمی‌خواند. یعنی **اگر این روت خالی
برگرداند، صفحه‌ی اخبار فارکس خالی می‌ماند** و اپ می‌نویسد «چیزی منتشر نشده».

آخرین اندازه‌گیری (۲۰۲۶-۰۹-۰۲): `GET https://coineprofx.com/api/academy/bn/news` → ۲۰۰، بیست خبر
فارسی از همان روز. یعنی امروز سالم است. دو چیز باید درست شود:

**۴.۱ — فیلد `image` رشته‌ی `"None"` می‌فرستد.**

```json
{"items":[{"id":"6168","title":"…","image":"None", …}]}
```

`"None"` همان `None` پایتون است که به‌جای `null` سریالایز شده. اپ آن را «عکس ندارد» می‌فهمد و
رد می‌کند، ولی درست نیست:

- اگر عکس دارید: URL کامل `https://…` بفرستید.
- اگر ندارید: `null` واقعی JSON بفرستید، نه رشته.

صفحه‌ی اخبار حول عکس طراحی شده؛ خبر بدون عکس درست چیده می‌شود ولی ضعیف‌تر است.

**۴.۲ — پایداری.** این روت نباید خالی برگردد مگر واقعاً خبری نباشد. اگر قرار است زمانی خالی
باشد، همان `{"items":[]}` را با ۲۰۰ بدهید (نه ۵۰۰) — اپ آن را «خبری نیست» نشان می‌دهد.

**شکل مورد انتظار** (همین است، تغییرش ندهید):

```json
{"items":[{"id":"6168","title":"…","summary":"…","url":"https://…",
           "image":"https://… یا null","source":"CoinePro FX",
           "published_at":"2026-09-02T11:25:25+00:00"}]}
```

## کار ۵ — روت تقویم: `academy/bn/calendar` (اولویت: بالا)

آخرین اندازه‌گیری: ۲۰۰ با ۵۱ رویداد هفته و `actual` که با انتشار داده‌ها پر می‌شود. **این روت را
هر دو پلتفرم می‌خوانند** — کاربر کریپتو هم همین تقویم را می‌بیند، چون تصمیم نرخ بهره روی USDT

## کار ۶ — تأیید Play Integrity (اولویت: متوسط، امنیتی)

اپ روی درخواست‌هایی که پول یا اعتبارنامه جابه‌جا می‌کنند دو هدر می‌فرستد:

| هدر | مقدار |
|---|---|
| `X-Play-Integrity` | توکنی که Google Play صادر کرده |
| `X-Play-Integrity-Nonce` | nonce که توکن به آن bind شده |

**روت‌های سمت شما که این هدرها را می‌گیرند** (فقط `POST`/`PUT`/`PATCH`):

- مسیرهایی که به `/login` ختم می‌شوند — ورود
- مسیرهایی که به `/execution/connections` ختم می‌شوند — ذخیره‌ی کلیدهای صرافی

**nonce چطور ساخته می‌شود** (تا بتوانید بازمحاسبه کنید):

```
nonce = base64url_nopad( SHA-256( "METHOD path minute" ) )
minute = floor(epoch_millis / 60000)
```

`path` همان `encodedPath` درخواست است، `METHOD` با حروف بزرگ. یک فاصله بین هر سه.

**کاری که سرور باید بکند**

1. توکن را با Play Integrity API (`decodeIntegrityToken`) و همان Cloud project number باز کنید.
2. چک کنید `requestDetails.nonce` برابر هدر nonce باشد، و برابر nonce بازمحاسبه‌شده برای
   **دقیقه‌ی جاری یا دقیقه‌ی قبل** (اپ ممکن است روی مرز دقیقه بیفتد).
3. `requestDetails.requestPackageName == "com.coinepro.app"` و `timestampMillis` تازه باشد.
4. `appIntegrity.appRecognitionVerdict == PLAY_RECOGNIZED` و
   `deviceIntegrity.deviceRecognitionVerdict` شامل `MEETS_DEVICE_INTEGRITY`.
5. سیاست را شما تعیین می‌کنید. پیشنهاد ما:
   - روی `login`: verdict بد یا هدر غایب ⟵ **مسدود نکنید**، مرحله‌ی دوم بخواهید (کد ایمیل).
   - روی ذخیره‌ی کلید صرافی: verdict بد ⟵ رد کنید.

**نکته‌ی مهم:** اپ هرگز خودش امتناع نمی‌کند. گوشی بدون Play Services، شبیه‌ساز، یا شبکه‌ای که
به Google نمی‌رسد، درخواست را **بدون این دو هدر** می‌فرستد. در بازار ایران این حالت نادر نیست،
پس «هدر ندارد» را با «verdict رد شد» یکی نگیرید.

سند کامل: `docs/security/INTEGRITY.md` در مخزن اپ.

## کار ۷ — پین‌های TLS (اولویت: متوسط، هماهنگی لازم)

اپ `CertificatePinner` دارد و تا وقتی پین ندهیم خاموش است. برای روشن‌کردنش لازم داریم:

- **SHA-256 SPKI pin گواهی فعلی** `coineprofx.com` (leaf یا intermediate — کدام را انتخاب
  می‌کنید بگویید).
- **یک پین پشتیبان** برای کلیدی که هنوز صادر نشده. بدون پشتیبان، اولین تمدید گواهی همه‌ی
  کاربران را قفل می‌کند و راه برگشتی جز انتشار نسخه‌ی جدید در Play نیست.

```bash
# گرفتن پین از گواهی فعلی
openssl s_client -connect coineprofx.com:443 -servername coineprofx.com < /dev/null 2>/dev/null \
  | openssl x509 -pubkey -noout \
  | openssl pkey -pubin -outform der \
  | openssl dgst -sha256 -binary | base64
```

**قرار کاری:** هر تغییر گواهی/کلید باید **حداقل ۳۰ روز قبل** اعلام شود تا نسخه‌ی جدید اپ با پین
تازه منتشر و نصب شود. سند: `docs/security/PINNING.md`.

  بگویید.
