# To the web terminal (Bazaarnama / `indicators.js`) — four indicator defects, found by an outside reference

From the Android app, 4.49.0. The app's engine is a port of the terminal's `indicators.js`, and a
120-bar fixture recorded from that file (`chart/core/src/jvmTest/resources/indicator-parity.txt`)
has held the port to 1e-6 since the port was made. In 4.49.0 the same fixture was run through an
outside reference — the `ta` Python library, and TA-Lib's / TradingView's definitions written
out where `ta` departs from them (`scripts/quality/gen_indicator_reference.py`). Fifty-nine
series agree with the reference to 1e-6. Four classes of series do not, and the JavaScript has
the same four, so this is a report rather than a divergence:

| Series | What the JavaScript does | What the definition does | Effect on the screen |
| --- | --- | --- | --- |
| MACD signal, MACD histogram | runs the 9-bar EMA over the whole MACD array with the undefined head (bars 0–24) read as `0` | starts the EMA at the first defined MACD value (bar 25), reports from bar 33 | a signal line is drawn eight bars early, pulled towards zero, and the pull decays over ~40 bars (`0.8^n`); the histogram inherits it |
| Force index (13) | counts bar 0 as a zero change and seeds the EMA on it | bar 0 has no change; the EMA seeds on bar 1 and reports from bar 13 | the first ~40 readings biased towards zero |
| TRIX (18) and its signal | reports after one stage of three has settled (bar 18) | reports after all three (bar 52); the signal from its first defined value | a line drawn from one sample smoothed three times, for 34 bars |
| SMI ergodic (20, 5, 5) and its signal | counts bar 0 as a zero change; the second stage reports from a single sample | each stage waits its own period; reports from bar 24 | same shape as TRIX |

The app now does what the definition does. Its parity test therefore no longer compares those
seven series with the terminal's fixture (`IndicatorParityTest.CORRECTED_SINCE_WEB`); the day
`indicators.js` is fixed and the fixture re-recorded, deleting the names from that set brings
the comparison back.

One convention to state, because it is a choice and not a defect: the EMA family (EMA, MACD,
PPO, PVO, TSI, KAMA, Keltner's basis) seeds with the **first value**, the pandas / `ta` way. TA-Lib
and TradingView's `ta.ema` seed with the SMA of the first *n*; the two agree to 1e-6 after about
five periods and differ before. Both the app and the terminal use the first-value seed, so a
reader comparing either with TradingView will see a transient at the far left of a fresh chart
and nothing after. Changing it would be a change to both at once, and is not asked for here.

Nothing is needed from the terminal for the app to ship; this is so the two stop disagreeing.
